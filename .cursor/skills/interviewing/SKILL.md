# Interviewing Skill

## Purpose
Proactively interview the user to clarify ambiguity before writing code. Enforces the non-negotiable engineering principle: Never guess or assume unspecified requirements.

## Activation Criteria
Activate this skill whenever:
- User requirements lack concrete technical specifications or acceptance criteria.
- Database schema attributes, relationship cardinalities, or migration strategies are unspecified.
- API request/response payloads, authentication mechanisms, or status codes are ambiguous.
- User interface layout, component interactions, or responsive breakpoints are not detailed.
- Edge cases, error handling behavior, or fallback scenarios are unmentioned.

## Procedure
1. **Analyze Requirements:** Examine the user request to identify all missing constraints, implicit assumptions, and architectural gaps.
2. **Formulate Targeted Questions:**
   - Group related questions by domain (Architecture, Database, Security, UI/UX).
   - Frame questions with clear multiple-choice options or recommended approaches.
   - Outline trade-offs and rationale for each proposed option.
3. **Present Questions:** Submit questions directly to the user and pause execution.
4. **Ingest User Feedback:** Incorporate user choices into the technical plan before proceeding to implementation.
